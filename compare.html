      Compared

      Open Notch, Agent Notch and Boring Notch, side by side.

      Three apps that live in the notch. Two watch coding agents; one does music and calendars. We measured all three on one Mac, read their own pages and bundles for the rest, and marked our own gaps the same way as theirs.

      Performance

      Open Notch is the lightest of the three, by a wide margin on memory and on the cost of opening. Idle CPU is a near tie with Boring Notch.

      Features

      For watching and talking to coding agents it does the most. Approving works for Claude Code and Codex, answering questions for Claude Code only; Agent Notch’s site does not say which agents it covers. It does none of Boring Notch’s music, calendar or HUD.

      Design

      A matter of taste, so only what can be checked is here. Open Notch is one black theme; Agent Notch ships light ones too.

      Accessibility

      Open Notch had real gaps, and the worst were fixed before this page. The other two were not tested with VoiceOver, so no claim is made about them.

      // Performance

      Measured on 8 October 2026, on one MacBook Pro (macOS 26), each app launched fresh and left to settle for two minutes. Lower is better in every chart.

      How this was measured
      • CPU is the process’s own cumulative CPU time over the window, from ps, the figure Activity Monitor shows. 100% is one core.
      • Memory is the process’s footprint from footprint, not resident size.
      • Each app was started alone by the same script, left for 120 seconds, then measured. Opening is driven by moving the real pointer onto the notch, so each app’s own hover handling runs.
      • Warm-up is real and is excluded. In its first two minutes Open Notch used about 0.3% idle and ~100 ms per open while it read a day of agent logs; Agent Notch used 58% in its first minute. The charts show what each settles to.
      • Open Notch watched four live synthetic agents. The other two were given the same four processes but no agent hooks, so they were idle in the way an app with nothing to show is idle; with real agents running they would do more, and so would Open Notch.
      • Versions: Open Notch 0.0.1, Agent Notch 2.1.8, Boring Notch 2.7.3, as installed on this Mac.
      • One machine, one settled run each; earlier runs with a shorter settle gave the same ordering. Treat the ratios as the finding, not the last digit.
      • Reproduce it: NOTCH_X=864 BENCH_SETTLE=120 python3 scripts/bench/bench.py <binary> quiet 60, and hover 60.

      // Design

      Taste can’t be measured, so this is only what can be checked in the product.

      What Open Notch does

      • Black like the hardware, one accent colour used only as a surface, and text in three weights of attention.
      • Corners are concentric: the card’s radius is the notch’s radius minus the gap around it, on every page.
      • A quiet row is two lines in 46 points. Only “needs you” is a word; everything else is a mark.
      • Motion is springs that carry velocity; with Reduce Motion on, it fades instead.

      Where it falls short

      • One theme. Agent Notch ships light themes as well; Open Notch is black only.
      • It opens on hover. That suits the pointer. For the keyboard there is a separate way in, described below, but it is newer and less proven than the pointer path.

      // Accessibility

      What was checked for Open Notch, and what was not checked for the others.

      Open Notch, checked

      • VoiceOver: before this release, no row, tab or button in the notch said anything useful. Now every row is one button that reads “who, state, what it is doing, how long”, tabs are radio buttons, and a new “needs input” is announced. This was verified by reading the accessibility tree, not yet by a long session with VoiceOver.
      • Contrast: the quietest text was 3.7:1 on black, under the 4.5:1 that WCAG asks of small text. It is now 5.3:1; the other two weights are 6.9:1 and 19:1.
      • Reduce Motion and Increase Contrast are respected.
      • Keyboard: “Browse agents with the keyboard” in the menu-bar menu (or the open shortcut, once you turn shortcuts on) opens the notch and gives it the keys: arrows move between agents, Return goes to one, R replies, Tab changes page, Y, D and A decide a card, Esc gives the keys back. It was tested by sending those keys to the running app, not yet by someone who lives on the keyboard.

      Still missing

      • The keyboard path needs a deliberate first step (the menu or the shortcut). Hovering still opens the notch for a pointer only.
      • Agent Notch and Boring Notch were not tested with VoiceOver, so nothing is claimed about them. Agent Notch’s binary references Reduce Motion; that is all that was confirmed.

      // Where Open Notch loses

      • Not notarised. macOS warns on first launch. Agent Notch is notarised.
      • No automatic updates. That is deliberate (it never phones home), and it is also less convenient than both others.
      • Approvals reach two agents, questions one. You can approve Claude Code and Codex from the notch; questions can only be answered for Claude Code. Command Code offers no hook. Agent Notch’s setup offers approval replies for the same two, and its bundle also forwards OpenCode and Cursor prompts.
      • Claude limits read no login by default, so they are only as fresh as the last Claude Code session. Agent Notch always reads your Claude login from the Keychain and asks Anthropic; Open Notch does that only if you turn on Live Claude limits.
      • Exact state for four agents only (Claude Code, Codex, Command Code, OpenCode). Cursor, Kimi, Pi, LM Studio, Claude Desktop (Cowork) and the rest show as “Open” while they run, without what they are doing. In a live run Agent Notch read Claude Code and Codex in depth, monitored Cursor, Antigravity and Pi, and did not show the six running Command Code sessions at all.
      • Apple silicon, macOS 13+ only. Boring Notch runs on Intel too.
      • No music, calendar, HUD or AirDrop. It was never meant to.

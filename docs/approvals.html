      Using the notch

      Approvals and questions

      Allow, deny or answer an agent from the notch, what Always allow remembers, and the safety rules that decide what can be approved.

      With Claude Code’s hooks installed (notchyctl install claude --write), Claude asks the notch before it asks the terminal. The notch opens with a card:

      • A permission shows the exact command or path. For an edit, it shows the change itself, removed lines in red and added lines in green. Buttons: Allow, Deny, Say why…, and Always allow when there is something safe to remember. Terminal hands the decision back to Claude’s own prompt.
      • A question shows its options with their descriptions, and a field to type your own answer. A multi-select question lets you pick several, then Send. A prompt with several questions steps through them one by one.

      It never blocks you

      • If Open Notch is not running, the hook exits at once and Claude asks in the terminal as usual.
      • After 45 seconds with no answer, the decision goes back to the terminal. Change the wait in Settings → Approvals.
      • If that agent’s terminal is already in front of you, the notch steps aside and the terminal’s own prompt appears at once (on by default, in Settings → Approvals).
      • Terminal on the card, or killing the hook, does the same.

      Always allow

      Always allow is only offered for something that is safe to remember:

      • a plain command with no way to chain another (npm test, git status), and anything after it that is not another command;
      • edits to files inside the project’s folder;
      • a named MCP tool.

      It is never offered for a shell, sudo, curl | sh, or a compound command. The card says exactly what the rule means (Always allow means: Run "npm test", from now on.). Every rule is listed, and removable, in Settings → Approvals.

      When a command cannot be approved here

      A command with hidden characters (text-direction overrides, zero-width marks), or one too long to read on a card, is never allowed from the notch. The card says why, and Open Terminal replaces Allow.

      A card that has just appeared ignores clicks and keys on Allow for half a second, so an agent cannot time a request to land under a moving pointer.

      Say why

      Say why… turns Deny into a short note for the agent (“use the staging database instead”), sent back with the denial.

      Other agents

      Agent From the notch
      Claude Code Approve, deny, always allow, answer questions
      Codex Permission prompts: allow or deny from the notch, with the Codex hook. Its questions and Computer Use prompts show as Needs input; a click takes you to that chat
      Command Code Shows a permission dialog or question as Needs input; a click takes you there
      OpenCode Shows Needs input while it waits for an approval; a click takes you there

      Keyboard

      With shortcuts on: ⌃⌥Y allow, ⌃⌥D deny, ⌃⌥A always allow. They act only on a permission card that is on screen.

      Scripting

      notchyctl requests                                  # what is waiting
notchyctl respond <id> allow                        # or deny, defer
notchyctl respond <id> answer --answer 'Approach=Token bucket'

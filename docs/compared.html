      Reference

      Compared

      Open Notch measured and listed next to Agent Notch and Boring Notch: performance, features, design and accessibility, including where Open Notch loses.

      This is the plain-text version of the comparison page, with what was checked and how. Open Notch’s own gaps are marked the same way as the others’.

      The three apps are not the same kind of thing. Open Notch and Agent Notch watch coding agents. Boring Notch is a general notch utility (music, calendar, shelf, volume overlay) with no agent features at all.

      Performance

      Measured on 8 October 2026 on one MacBook Pro (macOS 26). Each app was started alone, left for two minutes, then measured. Lower is better.

      Open Notch 0.0.1 Agent Notch 2.1.8 Boring Notch 2.7.3
      Idle CPU (% of one core) 0.067 10.5 0.133
      Memory at rest 15 MB 115 MB 52 MB
      CPU to open and close the notch 7 ms 1,000 ms 507 ms
      Memory after 20 open/close cycles 15 MB 208 MB 58 MB

      How it was measured:

      • CPU is the process’s own cumulative CPU time over the window (what Activity Monitor shows; 100% is one core). Memory is the footprint from footprint.
      • Opening is driven by moving the real pointer onto the notch, so each app’s own hover handling runs.
      • Warm-up is excluded, and it is real. In its first two minutes Open Notch used about 0.3% idle and about 100 ms per open while it read a day of agent logs. Agent Notch used 58% of a core in its first minute. The table is what each settles to.
      • Open Notch watched four live synthetic agents. The other two were not given agent hooks, so they were idle the way an app with nothing to show is idle. With real agents running they would do more, and so would Open Notch.
      • One machine and one settled run each; earlier runs with a shorter settle gave the same ordering. The ratios are the finding, not the last digit.

      Reproduce it:

      NOTCH_X=864 BENCH_SETTLE=120 python3 scripts/bench/bench.py <binary> quiet 60
NOTCH_X=864 BENCH_SETTLE=120 python3 scripts/bench/bench.py <binary> hover 60

      NOTCH_X is the notch’s horizontal centre in points on your display.

      Design

      Taste can’t be measured, so this is only what can be checked.

      • Open Notch is black like the hardware, with one accent colour used only as a surface and text in three weights of attention. Cards are concentric with the notch on every page: the card’s corner radius is the notch’s minus the gap around it. A quiet row is two lines in 46 points.
      • It is one theme. Agent Notch also ships light themes. Open Notch is black only.
      • It opens on hover, which suits a pointer. The keyboard has its own way in (below), which is newer and less proven.

      Accessibility

      What was checked for Open Notch, and what was not checked for the others.

      • VoiceOver. Before this release no row, tab or button in the notch said anything useful. Now each row is a single button that reads who, state, what it is doing and how long ago, with a “Reply” action where a reply can reach it; tabs are radio buttons; icon and action buttons have names; and a new “needs input” is announced. This was verified by reading the accessibility tree the notch exposes, not yet by a long session with VoiceOver.
      • Contrast. The quietest text was 3.7:1 on black, below the 4.5:1 WCAG asks of small text. It is now 5.3:1. The other two weights are 6.9:1 and 19:1.
      • Reduce Motion and Increase Contrast are respected: the notch fades instead of springing, and text brightens.
      • Keyboard. “Browse agents with the keyboard” in the menu-bar menu (or the open shortcut, once shortcuts are on) opens the notch and gives it the keys: arrows move between agents, Return goes to one, R replies, Tab changes page, Y/D/A decide a card, Esc gives the keys back. Tested by sending those keys to the running app, not yet by someone who lives on the keyboard.
      • Agent Notch and Boring Notch were not tested with VoiceOver, so nothing is claimed about them. The one thing confirmed is that Agent Notch’s binary refers to the Reduce Motion setting.

      Where Open Notch loses

      • It is not notarised, so macOS warns on first launch. Agent Notch is notarised.
      • It has no automatic updates, on purpose (it never phones home), which is less convenient than both others.
      • Approvals reach two agents (Claude Code, Codex) and questions one (Claude Code). Command Code offers no hook. Agent Notch’s setup offers approval replies for the same two, and its bundle also forwards OpenCode and Cursor prompts.
      • It shows no Claude plan percentages. Agent Notch shows Claude’s 5-hour and weekly limits by reading your Claude login from the Keychain; Open Notch deliberately does not read it, so for Claude it shows the plan and token estimates instead.
      • It shows no model name on a row. Agent Notch does (“Opus 5.5”, “GPT-6.1 Sol”).
      • It reads exact state for four agents only (Claude Code, Codex, Command Code, OpenCode). Cursor, Kimi, Pi, LM Studio, Claude Desktop (Cowork) and the rest show as “Open” while they run. In a live run Agent Notch read Claude Code and Codex in depth, monitored Cursor, Antigravity and Pi, and did not show Command Code at all.
      • It runs on Apple silicon with macOS 13 or later. Boring Notch also runs on Intel.
      • It has no music, calendar, volume overlay or AirDrop, and is not meant to.

      Where Open Notch wins in the live run: every running Command Code session and the Command Code app; sub-agents grouped under their parent; sessions stay listed while they run, however long they have been idle.
